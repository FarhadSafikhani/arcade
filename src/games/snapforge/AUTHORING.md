# Snapforge level authoring

Snapforge is a static game. An LLM can draft a model, but level JSON is reviewed and committed before players see it. The game derives the fixed 3D model, guided breakup, physical brick pile, build order, ghost hints, and gallery preview from the same `bricks` array.

## Add a model

1. Give an LLM the prompt below and replace `[SUBJECT]`, `[PIECE COUNT]`, `[COLLECTION]`, and `[ORDER]`.
2. Save its JSON as `src/games/snapforge/levels/<id>.json`.
3. Run `npm run validate:snapforge`. Fix every error before continuing.
4. Run `npm run dev`, open `/arcade/games/snapforge/index.html`, and inspect the 3D gallery preview and full build from all four resting views at desktop and phone widths. Revise the JSON if the subject is hard to recognize or a target is obscured. Structural validation cannot judge visual likeness.
5. Increment `version` when changing an existing model so an incomplete saved build starts fresh. Use a unique lowercase slug `id`, a known `collection` (`starter`, `land-animal`, `fruit`, `bird`, `car`, `ocean`, or `dinosaur`), and an `order` unique within that collection. The menu derives titles, previews, piece counts, and unlock paths from the level files. The first model in each collection is playable immediately; each later model unlocks when the previous one in that collection is completed. Keep piece counts rising within each collection.

The five Starter models are Little Duck, Apple, Pineapple, Sports Car, and Castle. The themed collections contain three models each. The files for the themed models are generated by `python scripts/generate-snapforge-collections.py`; edit that source when changing their geometry, then regenerate and validate the JSON. Review each generated model in the 3D preview and build screen, since structural checks do not establish visual likeness.

The coordinate system uses integer studs: `x` and `y` are horizontal axes and `z` is the layer. An optional `h` is either `1` or `2`, defaulting to `1`. Height-2 pieces have smooth sides and studs only on top. `w` and `d` are positive rectangular stud dimensions. A 2×4 and 4×2 of the same height and color are interchangeable during play; the selected piece rotates into the target orientation automatically. All coordinates begin at zero. Colors are names from the level's six-digit hex `palette`. A brick above ground needs at least one stud of overlap with a brick directly below it. Bricks occupy every layer from `z` through `z + h - 1` and cannot share an occupied stud cell. The whole model must be connected. The game sorts pieces from bottom to top for construction and reverses that order for the opening breakup.

## Prompt template

> Design a recognizable brick-built **[SUBJECT]** for Snapforge, using about **[PIECE COUNT]** rectangular pieces. Return **only valid JSON**, with no Markdown. Use this exact shape:
>
> `{ "id": "lowercase-slug", "title": "Display name", "description": "One short sentence.", "collection": "[COLLECTION]", "order": [ORDER], "version": 1, "palette": { "color-name": "#RRGGBB" }, "bricks": [ { "id": "unique-slug", "x": 0, "y": 0, "z": 0, "w": 2, "d": 2, "h": 1, "color": "color-name" } ] }`
>
> Think in layers first. Build a recognizable 3D model from several quarter-turn views, then divide each layer into non-overlapping rectangular bricks. Use a few contrasting colors for defining details such as eyes, wheels, or windows. Every `x`, `y`, and `z` must be a non-negative integer; every `w` and `d` must be a positive integer. Use `h: 2` to replace two directly stacked, same-color bricks with identical footprints; otherwise omit `h` or use `1`. Pair longer identical stacks from bottom to top, leaving a single brick for an odd remainder. Preserve the occupied shape and colors, and count each chunky brick as one piece. Keep all brick IDs unique. Every raised brick must overlap at least one stud in the layer directly beneath it, and the model must be connected. Do not invent unsupported special shapes, slopes, plates, or floating pieces. Include all bricks needed to make the shape; the player will find them in a physical pile. Make the first few layers broad enough to support details above. Check the JSON yourself for collisions before returning it.

`npm run validate:snapforge -- path/to/candidate.json` checks one candidate file. The validator checks geometry and metadata; the in-game preview is the final check for readability and visual quality.

Every fresh build starts at 0 placed pieces; never omit construction steps or pre-place bricks to meet a piece-count budget. Use as many pieces as the model needs, including 100 or more. Excess pile duplicates are held in reserve and replenished during play; see `docs/design.md`.
